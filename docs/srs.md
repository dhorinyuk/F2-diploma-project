# Специфікація вимог до програмного забезпечення (SRS)
**Проєкт:** Intelligent Web Platform for Vehicle Condition Analysis and Failure Prediction  
**Стандарт:** ISO/IEC/IEEE 29148:2018  
**Статус:** Approved (Baseline v1.0)  

---

## 1. System Context (Контекст системи)
Платформа аналізу технічного стану транспортних засобів та прогнозування несправностей є хмарною аналітичною системою, призначеною для безперервного моніторингу телеметрії CAN-шини/OBD-II, виявлення експлуатаційних аномалій та предиктивного розрахунку залишкового ресурсу критичних вузлів автомобіля (двигун, паливна система, трансмісія, гальмівний контур).

### Межі системи (Scope):
* **Вхідний контур:** Приймання структурованих потокових даних параметрів датчиків (оберти двигуна, тиск масла, температура охолоджувальної рідини, тиск наддуву, довготривала паливна корекція) та діагностичних кодів несправностей (DTC) через протокол HTTPS від IoT-телематичних контролерів або мобільного шлюзу.
* **Аналітичний контур:** Попередня обробка часових рядів, статистичний аналіз відхилень, виконання інференсу моделей машинного навчання для оцінки ймовірності відмови вузла.
* **Зовнішні інтеграції:** Взаємодія з провайдерами авторизації (OAuth2/OIDC), шиною повідомлень для асинхронного розрахунку та каталогами нормативно-технічної документації СТО через зовнішні REST API.

## 4. Verification Criteria (Критерії верифікації вимог)

* **SRS-FUN-01, SRS-FUN-03:** Верифікуються за допомогою інтеграційних тестів у середовищі PyTest з мокуванням вхідного потоку через Postman/Newman-колекції та валідацією схем DTO через Pydantic.
* **SRS-NFR-PERF-01, SRS-NFR-PERF-02:** Верифікуються автоматизованим навантажувальним тестуванням утилітою **k6** (сценарій Spike Testing та Stress Testing з симуляцією 500–1000 паралельних віртуальних клієнтів (VU)).
* **SRS-NFR-PERF-03:** Перевіряється бенчмарк-тестами Python (`pytest-benchmark`) для вимірювання затримки виконання інференсу нейромережі на тестових вибірках часових рядів.
* **SRS-NFR-SEC-01, SRS-NFR-SEC-02:** Перевіряються інструментом статичного аналізу безпеки коду **SonarQube**, сканером вразливостей образів контейнерів **Trivy** у CI/CD, а також тестами верифікації заголовків безпеки OWASP ZAP.
* **SRS-NFR-REL-01:** Верифікується підсистемою моніторингу **Prometheus** та візуалізується дашбордами **Grafana** через розрахунок метрики `rate(http_requests_total{status=~"5.."}[5m])`.

## 5. Glossary (Глосарій термінів)

1. **OBD-II Telemetry (On-Board Diagnostics II)** — стандартизований цифровий інтерфейс бортової діагностики автотранспорту, що надає параметри роботи двигуна та систем автомобіля в режимі реального часу через параметри PID (Parameter ID).
2. **DTC (Diagnostic Trouble Code)** — стандартизований п'ятизначний літерно-цифровий код помилки (SAE J2012 / ISO 15031), що фіксується електронним блоком керування (ECU) при виході параметрів за межі норми.
3. **Hypertable (TimescaleDB)** — логічна абстракція над реляційними таблицями PostgreSQL, що автоматично розбиває дані часових рядів на часові та просторові чанки (chunks) для оптимізації операцій масового запису й агрегації.
4. **Latency (p95)** — 95-й процентиль затримки відповіді сервера: означає, що 95% усіх виконаних запитів обробляються швидше за вказане граничне значення (200 мс).
5. **JWT (JSON Web Token)** — компактний, URL-безпечний засіб передачі прав доступу між сторонами у форматі криптографічно підписаного JSON-об'єкта.
6. **Circuit Breaker** — інженерний патерн відмовостійкості розподілених систем, що запобігає каскадному падінню сервісів шляхом тимчасового блокування запитів до збійного зовнішнього компонента.
